# 👑 NADKING — The King of all Nads

Official memecoin website for **$NADKING**, launching on [Nad.fun](https://nad.fun) on Monad mainnet (chain id `143`).

Built with Next.js 15 (App Router), TypeScript, Tailwind CSS v4, Framer Motion, and viem.

---

## ⚡ Quick start (local dev)

```bash
# 1. install
npm install

# 2. copy env file
cp .env.example .env.local

# 3. run dev server
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) — you should see the full site with placeholder stats.

### Build & verify production output

```bash
npm run build
npm start
```

The build must exit `0` with no type errors. Lighthouse can be run locally with the Chrome DevTools "Lighthouse" panel against `http://localhost:3000`.

## 🚀 Deploy to Vercel

The fastest path:

1. Push this repo to GitHub.
2. Visit [vercel.com/new](https://vercel.com/new), import the repo.
3. Add the env vars from `.env.example` in **Project Settings → Environment Variables**.
4. Click **Deploy**. Done.

Alternatively, use the Vercel CLI:

```bash
npm i -g vercel
vercel
vercel --prod
```

## 🪙 After token launch — update the contract address

Once your token is live on Nad.fun, do **one** of the following:

### Local

Edit `.env.local`:

```env
NEXT_PUBLIC_CONTRACT_ADDRESS=0xYourTokenAddressHere
```

Restart `npm run dev`.

### Production (Vercel)

1. Go to your Vercel project → **Settings → Environment Variables**.
2. Add or update `NEXT_PUBLIC_CONTRACT_ADDRESS` with the deployed address.
3. Redeploy (or just push a commit — Vercel will rebuild).

The site automatically:

- Switches the **Buy on Nad.fun** button to point at the token page (`nad.fun/token/<CA>`).
- Switches the **View Chart** button to DexScreener (`dexscreener.com/monad/<CA>`).
- Enables the **copy contract** button in the footer.
- Marks the `/api/stats` endpoint as `live` and starts reading on-chain `totalSupply` via Monad RPC.

> Market cap, holders, and 24h volume require an indexer or DEX API on Monad — wire them up in `src/app/api/stats/route.ts` when the data source is available.

## 🎨 Customizing copy & styling

| What | Where |
| --- | --- |
| Tagline / sub-tagline / supply | `src/lib/config.ts` (`SITE` object) |
| Lore paragraphs | `src/components/Lore.tsx` (`PARAGRAPHS` array) |

| Logo / hero artwork | `public/assets/` — see [Image assets](#-image-assets) |
| OG share image | `public/og.png` (regenerate with `npm run optimize-images`) |

## 🖼️ Image assets

All artwork lives under `public/assets/`:

```
public/
├── og.png                       ← 1200×630 social card (auto-generated)
├── icon.png                     ← 512×512 PWA icon (auto-generated)
├── apple-touch-icon.png         ← 180×180 iOS icon (auto-generated)
├── favicon.svg
└── assets/
    ├── logo.png                 ← Navbar + footer monogram
    ├── post-1.png               ← Twitter announcement banner (not embedded; use for socials)
    ├── king/
    │   ├── king-1.png           ← Hero centerpiece
    │   ├── king-2.png           ← Lore section illustration
    │   ├── king-3.png           ← Tokenomics donut center portrait
    │   └── king-4.png           ← Footer royal emblem
    └── emoji/
        ├── 2.png – 6.png        ← Roadmap phase icons (5 used)
        └── 7.png                ← Spare
```

**To swap any image:** drop a replacement file at the same path with the same name and refresh.

**To regenerate derived images** (`og.png`, `icon.png`, `apple-touch-icon.png`) after changing the source artwork:

```bash
npm run optimize-images
```

This script (in `scripts/optimize-images.mjs`) uses sharp (already installed via `next/image`) to resize and pad source images into web-ready outputs.
